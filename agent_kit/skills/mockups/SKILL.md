# Mockups

Boards are generated by the project's Python generators and rebuilt with
`agent-kit mockups …`. Run agent-kit the way the project pins it (for example a
`package.json` script such as `pnpm mockups:build`), otherwise
`uvx --from <agent-kit source> agent-kit …`. Never edit a generated
`.excalidraw`, `.svg`, `.png`, `board.json` or `index.html` by hand: change the generator and
rebuild. Mockups are schematic: they do not replace the application or its tests.

## Project layout

```
design/
  boards.json                 sections, boards, generators and settings
  index.html                  generated table of contents (open in a browser)
  scripts/                    the project's generators and drawing helpers
  wireframes/
    NN-section/<board>/       board.json and states/<frame>.excalidraw|svg|png
    patterns/<board>/         catalogs of shared parts: <board>.excalidraw|svg|png
```

Sections follow the application's navigation (`00-shell`, `01-auth`, …). A board
covers one screen or one shared part; it never duplicates frames of another board.
A screen board has no whole-board image: `board.json` keeps its groups, codes,
titles, subtitles and flows, and `index.html` shows them with the frames. Open a
frame's `.excalidraw` to look at it in Excalidraw.

## Board conventions

- **Group = one scenario or topic**, titled `NN · Тема`, ordered: main view →
  user actions → loading → empty states → errors. A group of sequential steps
  is a *flow*: frames go left to right and arrows join them.
- **Frame = one state.** Its title is `N.M · Название`, where `N.M` is the group
  and the position, assigned by the tools. Never write codes by hand and never
  reference another board's codes; refer to a frame by `board/state`.
- **Subtitle** — one line under the title, starting lower-case: the condition or
  action and its result («нажато «Сохранить» → ошибка под полем, форма сохранена»).
  It must fit the frame width.
- **On the frame only the interface**, with real interface copy and plausible
  fictional data reused across boards. No notes, statuses or explanations on the
  screen; whatever needs explaining goes into the subtitle, or the frame is split.
- **Edge cases are separate frames**: long names, empty optional fields, many pages.
- **Mobile** — a phone viewport (default 360×800) centred in the frame, marked by
  a `DesignReviewViewport` element; its label or group says `360 px`. In an ordinary
  group the mobile frame sits next to its desktop frame; a mobile flow gets its own
  group titled `… · 360 px`.
- **Labels are in the board language** set in `boards.json`; component names
  listed in `labels.allowLatin` and paths may stay as they are.
- **No process history anywhere**: no dates, «accepted/proposed/NEW», step
  numbers, ticket or document links, superseded variants. A rejected variant is
  deleted, not kept.
- Developer details invisible on the board may live in element `customData`
  (component, variant, action).

## Generators

A generator builds canvases and hands them to the board writer:

```python
import boardkit  # put on PYTHONPATH by the build

variants = [('login-empty', 'Вход · исходный экран, фокус на телефоне', canvas), ...]
groups = [('Вход', ('login-empty', 'login-filled', 'login-mobile')), ...]
boardkit.write_board(scene, variants, groups, OUT,          # OUT = design/wireframes/01-auth/login
                     flows=['Смена страницы'], frame_height=960)
```

- `variants`: `(state, 'Title · subtitle', canvas)`; `state` is kebab-case and
  names the file in `states/`. `groups` list every state once.
- `Canvas` and `scene` are drawing helpers: start with `from canvas import Canvas, scene`
  (shipped with agent-kit, on PYTHONPATH during the build) or bring your own; the
  required interface is documented at the top of agent-kit's `mockups/boardkit.py`.
- Generators run only through the build: `boardkit` and `canvas` are importable there.
- `frame_height` is shared by all frames of a board (taller screens may use more).
- Reuse shared drawing helpers; inspect their other consumers before changing them.
- Catalogs in `patterns/` draw one sheet and write it with
  `boardkit.write_scene(path, scene)` plus its SVG; their groups and items follow the
  same `NN · …` and `N.M · …` numbering.

## Build and check

Run after every change, from the project:

```
agent-kit mockups build      # regenerate, render PNG, index, validate
agent-kit mockups check      # same, and fail if boards were stale
agent-kit mockups validate   # validate only
```

Add `--design <dir>` when the design folder is not `design/` at the git root.
The build regenerates boards in `boards.json` order, renders PNGs for changed
SVGs (Node + Playwright), writes `index.html` and runs the validator. Regeneration
is idempotent: an unchanged generator changes no file.

The validator checks layout and registry, exports and PNG freshness, group and
frame numbering, one-line subtitles in the board language, mobile viewport size
and labelling, forbidden process wording, and that the index is current. It does
not judge design quality: look at the rendered PNGs of every changed frame
(long text, clipping, narrow layouts) before reporting, and say what you looked at.

## Set up in a new project

1. Run `agent-kit mockups init`: it creates `design/boards.json`, `design/scripts/`
   and `design/wireframes/` and installs this skill. Then fill `design/boards.json`:

   ```json
   {
     "title": "Mockups",
     "locale": "en",
     "frameWidth": 1280,
     "mobile": { "width": 360, "height": 800 },
     "labels": { "script": null, "allowLatin": [] },
     "playwright": "package.json",
     "generators": ["scripts/generate-login.py"],
     "sections": [
       { "id": "01-auth", "title": "Sign-in",
         "boards": [{ "id": "login", "title": "Sign-in", "generator": "scripts/generate-login.py" }] }
     ]
   }
   ```

   `locale` (`en`/`ru`) sets the index language; `labels.script: "cyrillic"`
   requires Russian labels; `playwright` points to a package.json that depends on
   Playwright; `generators` run in order (a generator may read boards written
   before it).
2. Write the first generator (see Generators; the shipped `canvas.Canvas` is enough
   to start), then run the build and open `design/index.html`.
3. Ignore `__pycache__/` in git and exclude `design/` outputs from formatters.

## Scenario boards for a proposed change

A user-visible change is sketched as frames on the screen's board and discussed
there; a draft is not a decision. Show the current and the proposed state side by
side in one group until the change is decided, then keep only the decided frames.
